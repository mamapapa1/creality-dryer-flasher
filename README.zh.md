# Creality Space Pi X4 Lite - 固件刷写工具 (90 °C 改版)

适用于 **Creality Space Pi X4 Lite** 耗材烘干机的跨平台 (Windows / macOS / Linux) 刷写工具。它可以:

- **把最高温度从 75 提升到 90 °C** (167 → 194 °F, 最低降到 1 °C / 33.8 °F),
- 针对你的机器**校准**传感器读数,
- 随时**恢复到出厂固件**。

它是**一个自包含的文件 `flash.py`** -- 所有固件都内嵌其中, 无需再下载别的东西。界面支持
**5 种语言** (RU / EN / DE / ES / 中文), 全程只按数字操作, 写入后刷写工具会**把固件回读并逐字节校验**,
并在控制台显示 ST-Link 接线。刷写通过 SWD, 后端用 [pyOCD](https://pyocd.io/)
(`pip install pyocd`, 默认) 或 [OpenOCD](https://openocd.org/)。主板 MCU 为 **GD32F303CBT6**
(Cortex-M4, 软件兼容 STM32F303)。

## ⚠️ 安全 -- 接线前必读

> **最简单也最安全的方式是用 ST-Link 的 3.3 V 引脚给主板供电, 不接 220 V, 也不用单独的 5 V 电源。**
> 这样根本没有市电。当前批次的主板有电气隔离, 因此即使接着 220 V 也可以连接 ST-Link
> (见[《在 220 V 下刷写》](#在-220-v-下刷写进阶自担风险)), 不过普通刷写并不需要这样。

**如何拆开并接线 (推荐方式, 无 220 V):**

1. 撕掉底部的自粘脚垫以够到外壳螺丝。**用吹风机和酒精**把胶干净地揭下来, 把脚垫粘到胶带上以免落灰。
2. 四根线 ST-Link → 主板: **SWDIO、SWCLK、GND** 和 **3.3V → 主板的 3.3 V 电源轨 (MCU VDD)**。
3. **RST** 不需要 (否则会无限重启) -- 复位由软件完成。
4. **不要接 220 V。** 仅 3.3 V 供电时**显示屏不亮 -- 这是正常的**
   (它的供电/背光不在 3.3 V 轨上), SWD 刷写并不需要它。

**关于 3.3 V 的要点:**

- ST-Link 上的 `3.3V` 引脚必须是**输出** -- 廉价克隆版是输出, 而原装 ST-Link 的同名脚是
  `VTREF` (检测输入), 并不供电,
- 务必接到 **3.3 V 电源轨 (MCU VDD)** -- **往那里接 5 V 会烧毁芯片** (最大约 3.6 V),
- 若主板检测不到或电压被拉低, 说明克隆版电流不够, 这时给主板的 **5 V 输入接 5 V**
  (它给板载 3.3 V 稳压器供电)。

本改版解除了出厂温度限制, 自担风险使用。**厂家/卖家保修必定失效。** 烘干机的塑料外壳能轻松承受这个温度,
结构上就是为此设计的。头几次运行不要让烘干机无人看管。

### 在 220 V 下刷写 (进阶, 自担风险)

有时**不断开 220 V** 直接刷写/调试很方便 (例如加热时实时读温度)。这只有在
**数字部分与市电之间有电气隔离**时才安全。

**这块主板有电气隔离:**

- 供电来自一个**带变压器的隔离 AC-DC 模块** (35 V 次级电容),
- 加热器通过**光耦** (EL3063 → 可控硅) 来开关 -- 光耦的存在正是为了切断「市电 ↔ MCU」的联系,
- 模块附近有一个跨越隔离屏障的 **Y 电容**。

因此可以在 220 V 下直接连接 ST-Link。如果你的板是其他批次, 用万用表很容易复测隔离:

1. **断电时:** 测 **GND (SWD 处)** 与市电输入两脚 (L 和 N) 之间的通断 →
   应为**开路 / 兆欧级** (没有低阻通路 = 隔离)。
2. **(小心) 通电时:** 测主板 GND 与插座地线之间的交流电压 →
   隔离的主板显示**约 0 到几伏** (Y 电容漏电流), 未隔离的会显示几十/上百伏。

220 V 下实时刷写是可行的。额外保险: **用电池供电的笔记本** (拔掉充电器)。万一你的批次没有隔离,
出错的代价是烧掉笔记本/主板或触电, 因此拿不准时就用 **ST-Link 的 3.3 V 供电** (或给 5 V 输入接 5 V 以点亮显示屏),
**不接 220 V** -- 如安全章节开头所述。

## 你需要什么

- **SWD 调试器:** ST-Link V2 (最便宜最常见), 或 CMSIS-DAP, 或 J-Link。
- 接到主板 SWD 焊盘的**导线** (找 `J25`/SWD 焊盘: SWDIO、SWCLK、GND)。
- **Python 3.7+** 和一个刷写工具 -- **pyOCD** (推荐) 或 OpenOCD。

### 安装刷写工具

**推荐 -- pyOCD** (一条命令, 无需单独的二进制):

```bash
pip install pyocd
```

就这样。GD32F303 芯片的 CMSIS 包会在首次刷写时**自动安装** (需联网一次)。无需再下载或配置 PATH。

**备选 -- OpenOCD** (若已安装): 加 `--backend openocd`。安装:
macOS `brew install open-ocd`, Linux `sudo apt install openocd`,
Windows -- 把 [xpack-openocd](https://github.com/xpack-dev-tools/openocd-xpack/releases) 放进 PATH
(或 `--openocd C:\路径\openocd.exe`)。

> **Windows + ST-Link:** pyOCD 和 OpenOCD 都通过 libusb 与 ST-Link 通信 -- 若看不到调试器,
> 需要用 [Zadig](https://zadig.akeo.ie/) 装 WinUSB 驱动。

默认刷写工具会自动选后端: 有 pyOCD 就用它, 否则用 OpenOCD。若两者都没有,
刷写工具会在菜单里**直接提示安装 pyOCD** (`pip install pyocd`)。

## 使用

固件已**内嵌在 `flash.py` 中** -- 这是一个自包含的文件, 运行时不需要 `firmware/` 文件夹
(它放在仓库里只为校验/透明)。

简单模式 -- 运行后按数字:

```bash
python3 flash.py        # 或 ./flash.py (文件可执行)
```

步骤 (全是数字):

```
1. 语言:  1) Русский  2) English  3) Deutsch  4) Español  5) 中文

2. 刷什么?
     1) 90 °C / 194 °F (提高上限)
     2) 恢复出厂 (75 °C / 167 °F)
     0) 退出

3. 校准 (仅 90 °C 会问, 恢复出厂不问):
     偏移, °C [回车=+11 / 0 / 例如 9.5]      (+11 °C ≈ +20 °F)

4. 安全:  1=是 (刷写)  0=取消
```

依次 `回车、回车、回车、1` (语言 → 90 °C → 校准 +11 → 确认) -- 完成。

不用菜单 (命令行):

```bash
python3 flash.py --lang en                 # 界面语言 (ru|en|de|es|zh)
python3 flash.py --firmware mod90c --calibrate 11   # 90 °C 改版
python3 flash.py --firmware stock          # 恢复出厂 75 °C
python3 flash.py --firmware my_dump.bin    # 按路径指定任意固件
```

常用选项:

```bash
python3 flash.py --list                    # 显示可用固件
python3 flash.py --speed 300               # 连接出错时降低 SWD 速度
python3 flash.py --dump backup.bin         # 先备份当前固件!
python3 flash.py --build-only out.bin      # 只生成 .bin 不刷写 (无板测试)
python3 flash.py --backend openocd         # 用 OpenOCD 代替 pyOCD
```

**提示:** 首次刷写前最好备份你这块板的出厂固件:
`python3 flash.py --dump my_factory_backup.bin`。批次会有差异 -- 自己的备份总能恢复原样。

### 无板测试刷写工具

不接任何东西也能确认一切正常:

```bash
python3 flash.py --list                                  # 能否看到固件
python3 flash.py --help                                  # 所有选项
# 生成一个校准后的 .bin, 检查只改了 1 个字节:
python3 flash.py --firmware mod90c --calibrate 11 --build-only /tmp/t.bin
cmp -l firmware/mod_90c.bin /tmp/t.bin                   # 应只有 1 行 (C1 地址)
```

`--build-only` 不碰主板。真正刷写只能在连接调试器且**断开 220 V** 时进行 (见安全章节)。

## 温度校准

传感器是**非线性**的: 冷时几乎准, 但**加热时偏低** -- 越热偏得越多。校准会加一个固定偏移,
应针对**工作点 (~90 °C)** 来调。

**推荐偏移 `+11 °C` (≈ +20 °F)** -- 原因如下:

| | 不校准 | 加 `+11 °C` |
|---|---|---|
| 冷态 (室温 ~23 °C) | 显示 ~23 °C (准) | 显示 ~34 °C (偏高) |
| 加热到真实 90 °C | 显示只有 ~79 °C | 显示 ~90 °C (准) |

不加偏移时, 显示卡在 ~79 °C, 调节器认为「没烧够」就继续推 PTC 加热器 → 触发热保护切断,
造成**持续咔哒声**和偏低/虚假的读数。加 `+11` 后真实的 90 °C 能正确显示和调节 -- `90 = 90`
(代价是冷态不准, 但无所谓 -- 反正是热着烘)。

在交互菜单里直接按**回车** (应用 +11)。你也可以输入自己的数 -- 但 90 °C 通常就需要约 **+11**。
偏移支持**小数** (如 `10.5` 或 `11.3`), 也支持**负值** -- 如果显示反而偏高 (如 `-3`, 范围 ±30 °C)。

> 偏移单位是 **°C** (固件内部单位)。温度计是 °F 时: 把差值换算成 °C (除以 1.8)。
> 例如显示 174 °F、温度计 194 °F → 差 20 °F → `20 / 1.8 ≈ 11` → 偏移 **11**。

**如果 ~90 °C 时听到咔哒声** -- 把偏移再加几度 (例如到 `+12…+13`)。偏移越大, 调节器越早切断加热,
于是加热出口达不到真实的 ~120 °C, 双金属保护也就不再跳动。代价是腔内真实温度比设定值低几度
(通常可接受)。

**如何测量你机器的偏移:**

1. 把温度计 (热电偶) 插入**前面的 PTFE 管孔**。
2. 加热腔体, 让温度稳定。
3. 比较**烘干机**显示的和**温度计**显示的。
4. 偏移 = `温度计 − 显示`。例如显示 79、温度计 90 → 偏移 **+11**。

**如何应用:**

```bash
python3 flash.py --firmware mod90c --calibrate 11    # +11 °C (推荐)
python3 flash.py --firmware mod90c --calibrate 0     # 不校准 (出厂)
```

或直接 `python3 flash.py` -- 交互菜单会单独询问偏移
(回车 = 推荐的 +11, `0` = 不校准, 或你自己的数)。

偏移对**两个腔体通用** (用同一个传感器常数)。刷写后最好再用温度计核对一次, 必要时用更精确的值重刷。

> 技术上, 校准只改一个 float 常数 `C1` (`T = ADC·K − C1`, 出厂 `C1 = 50.0`) 为 `50.0 − 偏移`。
> 详见 [`docs/PATCHES.md`](docs/PATCHES.md) (俄文)。

## 咔哒声和温度梯度 -- 都正常

烘干时你会听到加热器附近的**咔哒声**, 并发现后壁和前部温度明显不同。这是**正常现象**, 不是故障:

- **后壁 (热风出口):** 约 **120 °C / 248 °F**。这是加热器自身的热极限 -- 到 ~120 °C (248 °F) 就断开,
  降到 ~115 °C (239 °F) 再接通。咔哒声就来自这里 (120 ↔ 115 循环) -- 是加热器的热保护, 不是固件 bug。
- **腔体前部 (温度计/耗材所在处):** 约 **90 °C / 194 °F**。这是工作温度, 调节按它来 --
  也是显示屏显示的 (校准后是准的)。
- **前后温差:** 约 **30 °C (54 °F)**, 即后壁的空气比前部约**热 ~33 %** (等价: 前部比出口约凉 ~25 %)。
  这是流通式腔体正常的温度梯度。

换句话说: 咔哒的不是「固件故障」, 而是加热器在出口处达到极限, 而前部维持设定的 90 °C (194 °F)。

**如果咔哒声碍事** -- 可以**增大校准偏移**来消除 (例如用 `+12…+13` 代替 `+11`): 调节器会更早切断加热,
出口达不到 ~120 °C, 双金属保护也就不跳。此时真实温度会比设定值低几度。见
[《温度校准》](#温度校准)。

## 两个固件 -- 区别

| 文件 | 最高温 | 适合谁 |
|------|:------:|------|
| `firmware/mod_90c.bin` | 90 °C / 194 °F | 把上限提到 90 °C |
| `firmware/stock_factory_75c.bin` | 75 °C / 167 °F | 恢复出厂 |

### 关于 E4 和安全

**E4** 是传感器/加热故障码。本改版**并未完全去掉 E4 保护**: 若真的断开/短路温度传感器 --
**E4 仍会触发**并切断加热 (已验证: 拔掉传感器 → 报错出现)。

改版真正放宽的是**欠温看门狗**: 出厂固件在温度未达**设定值的 85 %** (`0.85 × 90 = 76.5 °C`) 时会报 E4,
而被限制在 75 °C 的加热永远到不了这个阈值 → **一直 E4**。改版去掉的正是这个误触发, 以便能到 90 °C。
硬件保护也仍在 -- PTC 加热器按其构造温度自限。

## 改版到底改了什么 (给好奇者)

改版是对出厂固件 (128 KB, 加载到 `0x08000000`) 的字节补丁。完整对照见
[`docs/PATCHES.md`](docs/PATCHES.md) (俄文)。简而言之:

- 目标温度上下限 `75 → 90 °C` 和 `45 → 1 °C` (1 区和 2 区),
- 把菜单里设定值范围扩到 90,
- 去掉显示/调节温度在 80.0 °C 处的限制,
- 把欠温看门狗绕过 E4 处理 (传感器故障的 E4 仍保留)。

传感器函数和按设定值的调节**未改动** -- 到达目标后照常停止加热。

> 想深入 / 二次开发固件 (自定义校准、风扇转速、UI)? 关于主板和逆向的笔记见
> [`docs/REVERSE.md`](docs/REVERSE.md) (俄文)。

## 出问题怎么办

- **看不到调试器 / `No available debug probes`** → 检查线和驱动
  (Windows: 用 [Zadig](https://zadig.akeo.ie/) 装 WinUSB), 把 `--speed` 降到 `300` 或 `200`。
- **`unable to connect` / `init mode failed`** → 主板没接 5 V/3.3 V、SWDIO/SWCLK/GND 接触不良, 或速度太高。
- **pyOCD: `Target type ... not found`** → 包没来得及装好, 手动
  `pyocd pack install gd32f303cb` (需联网), 再重试。
- **pyOCD 在某块板上不稳** → 改用 OpenOCD: `--backend openocd`。
- **刷错固件 / 主板行为异常** → 刷 `stock` (或你的备份)。刷写不会把板变砖 -- SWD 始终可用。
