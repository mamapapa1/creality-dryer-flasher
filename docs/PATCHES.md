# Карта патчей (для любопытных и для проверки)

Все прошивки - это **байтовые патчи** заводского образа Creality Space Pi X4 Lite
(128 КБ, грузится с `0x08000000`, MCU GD32F303CBT6). Ниже - что именно и зачем
меняется относительно заводской `firmware/stock_factory_75c.bin`.

Адреса в таблице - **смещения в файле** (они же `0x08000000 + offset` в адресном
пространстве MCU). Дизассемблер: `arm-none-eabi-objdump -b binary -m arm -M force-thumb`.

## Патчи мода 90 °C (подъём предела + диапазон)

| Offset | Было → стало | Что это |
|--------|:------------:|---------|
| `0x00FA7` | `d0` → `e0` | `beq → b` в функции обработки температуры: снимает кламп показываемой/регулируемой величины на `800` (= 80.0 °C, `cmp r0,#800; movgt r0,#800`). Без этого выше 80 не подняться. |
| `0x01090` | `2d` → `01` | Мин. уставка, зона 1: `45 → 1` °C |
| `0x01096` | `4b` → `5a` | Макс. уставка, зона 1: `75 → 90` °C |
| `0x010A4` | `2d` → `01` | Мин. уставка, зона 2: `45 → 1` °C |
| `0x010AC` | `4b` → `5a` | Макс. уставка, зона 2: `75 → 90` °C |
| `0x01460` | `2d` → `01` | Нижняя граница уставки (ещё одно место): `45 → 1` |
| `0x014C8` | `2d` → `01` | `cmp r0,#45 → cmp r0,#1` в обработчике уставки |
| `0x0531C` | `4b` → `5a` | Верхняя граница диапазона уставки в меню: `75 → 90` |
| `0x0531E` | `a7` → `b9` | Сопутствующая константа диапазона уставки |
| `0x05332` | `a7` → `b9` | То же |
| `0x0536A` | `2d` → `01` | Нижняя граница диапазона: `45 → 1` |
| `0x053BC` | `a7` → `b9` | Сопутствующая константа диапазона |
| `0x053F0` | `4b` → `5a` | Верхняя граница уставки (другое место): `75 → 90` |
| `0x05402` | `4b` → `5a` | Верхняя граница уставки: `75 → 90` |
| `0x05450` | `2d` → `01` | Нижняя граница: `45 → 1` |
| `0x05464` | `2d` → `01` | Нижняя граница: `45 → 1` |
| `0x06E78`..`0x06E8F` | `ff…` → код | Вспомогательная процедура, дописанная в свободную (`0xFF`) область. Остаток отладки, её вызов в финальной сборке не задействован (init-редирект отменён). Безвредна, оставлена для побайтовой идентичности с проверенной сборкой. |

## Патчи watchdog недогрева (часть мода 90 °C)

Ещё **два** патча убирают ложный E4 «недогрева», чтобы можно было дойти до 90 °C:

| Offset | Было → стало | Что это |
|--------|:------------:|---------|
| `0x014EC` | `fd be` → `3d bf` | Меняет цель перехода `b.w 0x80032e8 → 0x8003368` (путь 1) |
| `0x01512` | `ea be` → `2a bf` | Меняет цель перехода `b.w 0x80032e8 → 0x8003368` (путь 2) |

### Что за `0x80032e8` и `0x8003368`

- **`0x80032e8` - watchdog недогрева.** Сравнивает фактическую температуру с
  `уставка × 0.85` (float-константа `0x3f59999a` = `0.85`):
  ```
  if (темп >= 0.85 × уставки)  → ОК
  else                          → error_state = 3  (E4)
  ```
  То есть это E4 «температура не доходит до 85 % от цели». При зажатом на 75 °C
  нагреве и уставке 90 порог `76.5 °C` не достигался → **вечный E4**, поэтому переход
  уводится на нормальный путь.
- **`0x8003368` - нормальный путь:** просто сбрасывает `error_state = 0`.

**Важно:** это НЕ отключает E4 целиком. Аппаратная неисправность датчика
(обрыв/КЗ термистора) идёт по другим путям и **по-прежнему вызывает E4** - сенсорная
защита сохранена. Снимается только ложный триггер «недогрева».

## Температурная калибровка (константа C1 @ `0x0A94`)

Это **не** часть модов, а отдельная необязательная правка, которую делает флэшер
по флагу `--calibrate`. Температура считается в функции пересчёта (~`0x08000900`):

```
8000924: vldr s0, [0x8000a94]     ; s0 = C1  (заводское = 50.0, float32)
800092a: vnmls.f32 s0, s3, s2     ; T = (ADC·K) − C1
8000932: vstr s0, [r4, #44]       ; запись температуры (float °C)
...
800097a: vmul.f32 s2, s0, #10.0   ; ×10
8000992: vstr s2, [r4, #96]       ; запись int (0.1 °C), её читают регулятор и watchdog
```

Поскольку и дисплей (`[r4+44]`), и регулировка/watchdog (`[r4+96]`) берут значение
из **одной** этой формулы, а константа C1 - общая для обеих камер, сдвиг C1 двигает
все температуры согласованно:

| Offset (°C) | C1 (было `50.0`) | байты @ `0x0A94` |
|:-----------:|:----------------:|:----------------:|
| 0 (завод)       | 50.0       | `00 00 48 42` |
| +11 (рекоменд.) | 39.0       | `00 00 1c 42` |
| +X              | `50.0 − X` | `struct.pack('<f', 50.0 − X)` |

`T_new = ADC·K − (50 − X) = T_old + X` - то есть к показаниям прибавляется `X` °C.
Найдено эмпирически по SWD: при дисплее 82 термометр в переднем отверстии показывал
~92 (нелинейно). Рекомендуемое **+11** даёт `дисплей = реальной` на рабочих 90 °C.

## Чего патчи НЕ трогают

- Функцию опроса датчика PTC (`0x08001BAC`) - она родная, заводская.
- Регулировку по уставке (нагреватель выключается при достижении цели).
- Самоограничение PTC-нагревателей - это аппаратная защита, от прошивки не зависит.

## Как воспроизвести самостоятельно

```python
# собрать mod_90c.bin из заводской
d = bytearray(open("stock_factory_75c.bin","rb").read())
patches = {
    0x00FA7:b"\xe0", 0x01090:b"\x01", 0x01096:b"\x5a", 0x010A4:b"\x01", 0x010AC:b"\x5a",
    0x01460:b"\x01", 0x014C8:b"\x01", 0x0531C:b"\x5a", 0x0531E:b"\xb9", 0x05332:b"\xb9",
    0x0536A:b"\x01", 0x053BC:b"\xb9", 0x053F0:b"\x5a", 0x05402:b"\x5a", 0x05450:b"\x01",
    0x05464:b"\x01",
    0x014EC:b"\x3d\xbf", 0x01512:b"\x2a\xbf",   # watchdog недогрева → нормальный путь
}
for off,val in patches.items():
    d[off:off+len(val)] = val
# (+ необязательная процедура 0x6E78, см. готовый bin)
open("mod_90c.bin","wb").write(d)
```
