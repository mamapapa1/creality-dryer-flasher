# Заметки по реверсу - для тех, кто хочет дорабатывать прошивку

Наблюдения по плате и стоковой прошивке Creality Space Pi X4 Lite, собранные при
создании мода. Цель - сэкономить время тем, кто захочет копать дальше (свой UI,
2-точечная калибровка, управление оборотами, замена датчиков и т.д.).

> **Достоверность.** Раздел [«Проверено»](#проверено-дизассемблер--живой-swd) -
> подтверждено дизассемблером и чтением живой RAM по SWD в этом проекте. Раздел
> [«Ориентировочно»](#ориентировочно-ранняя-прозвонка--перепроверить) - из более
> ранней прозвонки/попыток своей прошивки, **перепроверяйте перед тем, как полагаться**.
> Адреса даны для конкретного дампа, на другой ревизии могут отличаться.

---

## MCU и отладка

- **MCU:** GD32F303CBT6 - Cortex-M4, **128 КБ flash @ `0x08000000`**, программно
  совместим с STM32F303 (но это GD32: ID-коды свои).
- **SWD:** площадка `J25` (SWDIO, SWCLK, GND). RST не нужен - сброс программный.
- **DPIDR** `0x2ba01477`, **device id** `0x21040414`.
- **pyOCD:** родной таргет `gd32f303cb` (пак `GigaDevice.GD32F30x_DFP`). OpenOCD -
  через `target/stm32f3x.cfg` (он ошибочно считает flash 512 КБ - на программирование
  первых 128 КБ не влияет).
- Дамп всей прошивки: `pyocd cmd -t gd32f303cb -c "savemem 0x8000000 0x20000 dump.bin"`.
- Дизасм (Thumb-2): `arm-none-eabi-objdump -D -b binary -m arm -M force-thumb --adjust-vma=0x08000000 dump.bin`.

## Питание и гальваническая развязка

Цифровая часть (и, значит, SWD-земля) **развязана от сети 220 В**:

- питание от **изолирующего AC-DC модуля с трансформатором** (вторичка ~5 В, электролиты на 35 В),
- нагреватели коммутируются через **оптопары EL3063 → триак** - оптопара рвёт связь «сеть ↔ MCU»,
- у модуля стоит **Y-конденсатор** через барьер изоляции.

Это позволяет отлаживать под нагрузкой. На другой ревизии плату легко перепроверить
мультиметром (см. README, раздел «Прошивка под 220 В»).

## Проверено (дизассемблер + живой SWD)

### Температурный конвейер - главное для модов

Температура, которую видит **и дисплей, и регулятор, и watchdog**, считается в одной
функции (~`0x08000900`). Она проверяет CRC8 по буферу **цифрового датчика** (не NTC!),
парсит сырое значение и считает:

```
T = raw · K − C1          ; C1 = float32 @ 0x0A94, заводское 50.0
```

- `0x08000932  vstr s0,[r4,#44]`  - температура как **float °C** (для дисплея),
- `0x08000992  vstr s2,[r4,#96]`  - то же **× 10, как int** (0.1 °C) - это читают регулятор и watchdog.

Сдвиг **одной** константы `C1` двигает все температуры согласованно и одинаково для
обеих камер. См. [`PATCHES.md`](PATCHES.md#температурная-калибровка-константа-c1--0x0a94).

> **Датчик нелинеен:** на холодную почти точно, при нагреве занижает (~−11 °C к 90).
> Единственной константой C1 (постоянное смещение) идеально откалибровать весь
> диапазон нельзя - это компромисс под рабочую точку. Для точности по всему
> диапазону нужна **2-точечная калибровка** (наклон + смещение) или таблица -
> это уже доработка прошивки, а не патч.

### E4 / watchdog недогрева

- `0x080032E8` - **watchdog недогрева:** `if (T < уставка·0.85) → error_state=3 (E4)`.
  Константа `0.85` = float `0x3f59999a`.
- `0x08003368` - нормальный путь: `error_state = 0`.
- Мод перенаправляет два перехода (`0x14EC`, `0x1512`) с E4-обработчика на нормальный
  путь, чтобы 90 °C не давало ложный E4.
- **Аппаратная неисправность датчика (обрыв/КЗ) идёт другими путями и по-прежнему
  даёт E4** - то есть сенсорная защита остаётся, мод снимает только «недогрев».

### Уставка: клампы и диапазон

- Клампы целевой температуры (зоны 1/2): мин `0x1090/0x10A4` (`45`), макс `0x1096/0x10AC` (`75`).
- Диапазон уставки в меню: `0x531C/0x53F0/0x5402` (`75`), мин `0x536A/0x5450/0x5464` (`45`).
- Кламп показываемой/регулируемой величины на `800` (= 80.0 °C) - снимается байтом `0x0FA7`.
- Полная таблица - в [`PATCHES.md`](PATCHES.md).

### PTC-функция и «грабли» с вентилятором

- `0x08001BAC` - опрос датчика PTC, в норме вызывает `0x080035FC` (зональная логика +
  поддержание idle-вентилятора выключенным).
- **Грабли:** если запатчить эту функцию на «return 1» (как делали ранние noe4-сборки),
  пропускается вызов `0x080035FC` → **правый вентилятор крутится при включении**.
  Поэтому PTC-функция в моде оставлена **родной**.

### Карта RAM для живой отладки по SWD

- Глобальная база: **`0x200001A8`**. `[+16]=0x20000168`, `[+20]=0x2000056C`.
- Структура температуры: **`0x200000B4`** (= `[[0x200001A8+16]+16]`):
  - `+44` (`0x200000E0`) - текущая температура, **float °C**,
  - `+48` - второе значение (похоже, влажность, ×100),
  - `+96` (`0x20000114`) - температура **int ×10** (её сравнивает watchdog).
- В `0x2000056C+...` лежат float-коэффициенты пересчёта.
- Удобно ловить запись температуры watchpoint'ом: `wp 0x200000e0 4 w` → PC `0x08000938`.

## Ориентировочно (ранняя прозвонка - перепроверить)

> Снято при попытке писать прошивку с нуля, **часть не подтверждена**. Перед пайкой -
> проверяйте мультиметром/осциллографом. Важно: **штатную температуру стоковая
> прошивка берёт с цифрового датчика** (см. выше), а не с NTC.

- **Кнопки** PA2-PA5 (pull-down, нажата = HIGH): `⚙`=PA5, `▲`=PA4, `▼`=PA3, `L/R`=PA2.
- **Вентиляторы:** PA9 = вент.1 (TIM1_CH2), PA10 = вент.2 (TIM1_CH3), ШИМ ~25 кГц
  (фан-драйверу нужен именно ШИМ, статический уровень не крутит).
- **Нагреватели:** PB12/PB14 (открытый сток, **LOW = ВКЛ**, через оптопару EL3063 → триак).
  PB13/PB15 - резерв (OD).
- **Дисплей:** питание PA6, шина CLK/DATA = PB10/PB11, бит-банг (`START → 0x7E → cmd → STOP`).
  ЖКИ **YXD-BS0023-3**, сильно мультиплексный сегментный. Таблица шрифта во флеше ~`0x080069CE`,
  буфер дисплея в RAM `0x20000734`.
- **UART:** USART1 на PB6/PB7 (AFIO remap), `J26`, **9600 8N1** - удобно для логов.
- **NTC** (назначение в стоке не до конца ясно): RSER ≈ 4700 Ом, R0 = 100k, BETA ≈ 4100,
  NTC → GND, на PA0/PA1.
- **Датчик влажности:** 4 провода (I2C-подобный), читается бит-бангом, тип чипа не
  опознан (SHT/AHT?), пины не локализованы (кандидаты PB0/PB1).

## Идеи для доработки

- **2-точечная калибровка** температуры (наклон+смещение) вместо одного смещения C1 -
  снимет нелинейность по всему диапазону.
- **Управление оборотами вентиляторов** через ШИМ TIM1 (PA9/PA10).
- **Свой UI / порт движка дисплея** - самое трудоёмкое: ЖКИ мультиплексный, нужно
  извлечь шрифт + привязки сегментов (буфер `0x20000734`).
- **Логи по UART** (PB6, 9600) для отладки без SWD.

Всё это - модификации прошивки, а не байтовые патчи, начинать удобно со снятого
дампа и дизасма по адресам выше.
