# Creality Space Pi X4 Lite - флэшер прошивок (90 °C мод)

Кроссплатформенный (Windows / macOS / Linux) флэшер для филаментной сушилки
**Creality Space Pi X4 Lite**. Позволяет:

- **поднять максимальную температуру с 75 до 90 °C** (167 → 194 °F, минимум опускается до 1 °C / 33.8 °F),
- **откалибровать** показания датчика под свой экземпляр сушилки,
- в любой момент **откатиться к заводской прошивке**.

Это **один самодостаточный файл `flash.py`** - все прошивки зашиты прямо в него,
ничего больше скачивать не надо. Интерфейс на **5 языках** (RU / EN / DE / ES / 中文),
управление одними цифрами, после записи флэшер **читает прошивку обратно и сверяет
байт-в-байт**, а в консоли показывает схему подключения ST-Link. Заливка идёт по SWD через
[pyOCD](https://pyocd.io/) (`pip install pyocd`, по умолчанию) или
[OpenOCD](https://openocd.org/). MCU платы - **GD32F303CBT6** (ядро Cortex-M4,
программно совместим с STM32F303).

## ⚠️ БЕЗОПАСНОСТЬ - прочитайте до подключения

> **Проще и безопаснее всего - питать плату 3.3 В с пина ST-Link, без 220 В и без
> отдельного 5 В источника.** Тогда мейнса нет вовсе. На текущей ревизии платы есть гальваническая
> развязка, поэтому ST-Link можно подключать и при поданных 220 В
> (см. [«Прошивка под 220 В»](#прошивка-под-220-в-для-опытных-на-свой-страх-и-риск)),
> но для обычной прошивки это не нужно.

**Как вскрыть и припаять (рекомендуемый способ, без 220 В):**

1. Снимите нижние клейкие ножки, чтобы добраться до саморезов корпуса. **Используйте фен и спирт**, чтобы отделить клейкую часть без остатков и прилепите ножки на скотч, чтобы на них не осела пыль. 
2. Четыре провода ST-Link → плата: **SWDIO, SWCLK, GND** и **3.3V → шина 3.3 В платы (VDD MCU)**.
3. **RST** подключать не нужно (будет бесконечный ребут) - сброс программный.
4. **220 В не подавать.** Дисплей при питании от 3.3 В **не горит - это нормально**
   (его питание/подсветка идут не от шины 3.3 В), для прошивки по SWD это не важно.

**Важно про 3.3 В:**

- пин `3.3V` на ST-Link должен быть **выходом** - на дешёвых клонах это так, на
  оригинальном ST-Link одноимённый пин - `VTREF`-вход, питания он не даёт,
- подавать строго на **шину 3.3 В (VDD MCU)** - **5 В туда нельзя, убьёт чип** (макс. ~3.6 В),
- если плата не определяется или напряжение проседает - клону не хватает тока, тогда
  питать **5 В на 5-вольтовый вход** платы (он кормит штатный регулятор 3.3 В).

Мод снимает заводское ограничение температуры, использование на свой страх и риск.
**Гарантия производителя/продавца при этом однозначно слетает.** Пластик корпуса сушилки спокойно держит эту температуру,
конструктивно она на неё рассчитана. Не стоит оставлять сушилку без присмотра на первых прогонах.

### Прошивка под 220 В (для опытных, на свой страх и риск)

Иногда удобно шить/отлаживать **не отключая 220 В** (например, читать температуру
вживую при нагреве). Это безопасно **только если цифровая часть гальванически
развязана от сети**.

**На этой плате есть гальваническая развязка**

- питание - от **изолирующего AC-DC модуля с трансформатором** (вторичка на 35 В),
- нагреватели коммутируются через **оптопары** (EL3063 → триак) - оптопара
  существует именно для разрыва связи «сеть ↔ MCU»,
- у модуля стоит **Y-конденсатор** через барьер изоляции.

Поэтому ST-Link можно подключать прямо под 220 В. Если у вас другая ревизия платы,
развязку легко перепроверить мультиметром:

1. **Сеть отключена:** прозвонка между **GND (у SWD)** и обоими контактами сетевого
   входа (L и N) → должно быть **обрыв / мегаомы** (низкоомного пути нет = развязка есть).
2. **(аккуратно) сеть включена:** переменное напряжение между GND платы и
   заземлением розетки → изолированная плата покажет **~0-единицы вольт**
   (утечка через Y-cap), неизолированная - десятки/сотни вольт.

Живая прошивка под 220 В возможна. Доп. страховка: **ноутбук от батареи**
(без зарядки в розетке). Если на вашей ревизии развязки вдруг нет, цена ошибки -
убитый ноут/плата или удар током, поэтому при сомнениях питайте **3.3 В от ST-Link**
(или 5 В на 5-вольтовый вход для включения дисплея) **без 220 В** - как описано в начале раздела безопасности.

## Что нужно

- **Отладчик SWD:** ST-Link V2 (самый дешёвый и распространённый), либо
  CMSIS-DAP, либо J-Link.
- **Провода** к контактам SWD на плате (площадка `J25`/SWD: SWDIO, SWDCLK, GND).
- **Python 3.7+** и инструмент прошивки - **pyOCD** (рекомендуется) либо OpenOCD.

### Установка инструмента прошивки

**Рекомендуется - pyOCD** (ставится одной командой, отдельный бинарник не нужен):

```bash
pip install pyocd
```

Всё. CMSIS-пак для чипа GD32F303 флэшер **поставит сам** при первой прошивке
(нужен интернет один раз). Больше ничего качать и прописывать в PATH не надо.

**Альтернатива - OpenOCD** (если уже установлен): флаг `--backend openocd`.
Установка: macOS `brew install open-ocd`, Linux `sudo apt install openocd`,
Windows - [xpack-openocd](https://github.com/xpack-dev-tools/openocd-xpack/releases)
в PATH (или `--openocd C:\путь\openocd.exe`).

> **Windows + ST-Link:** и pyOCD, и OpenOCD общаются с ST-Link через libusb -
> если отладчик не виден, для него нужен WinUSB-драйвер (через
> [Zadig](https://zadig.akeo.ie/)).

По умолчанию флэшер сам выберет бэкенд: есть pyOCD - берёт его, иначе OpenOCD.
Если не найден ни один - флэшер **предложит установить pyOCD** одной командой
(`pip install pyocd`) прямо из меню.

## Использование

Прошивки **зашиты внутрь `flash.py`** - это один самодостаточный файл, папка
`firmware/` для работы не нужна (она в репозитории только для проверки/прозрачности).

Простой режим - запуск и ввод цифр:

```bash
python3 flash.py        # или ./flash.py (файл исполняемый)
```

Шаги (всё цифрами):

```
1. Язык:  1) Русский  2) English  3) Deutsch  4) Español  5) 中文

2. Что прошить?
     1) 90 °C / 194 °F (поднять максимум)
     2) Откат на заводскую (75 °C / 167 °F)
     0) выход

3. Калибровка (спрашивается ТОЛЬКО для 90 °C, для отката - нет):
     Смещение, °C [Enter=+11 / 0 / напр. 9.5]      (+11 °C ≈ +20 °F)

4. Безопасность:  1=да (прошить)  0=отмена
```

Последовательность `Enter, Enter, Enter, 1` (язык → 90 °C → калибровка +11 →
подтверждение) - и готово.

Без меню (CLI):

```bash
python3 flash.py --lang en                 # язык интерфейса (ru|en|de|es|zh)
python3 flash.py --firmware mod90c --calibrate 11   # мод 90 °C
python3 flash.py --firmware stock          # откат к заводской 75 °C
python3 flash.py --firmware my_dump.bin    # произвольная прошивка по пути
```

Полезные опции:

```bash
python3 flash.py --list                    # показать доступные прошивки
python3 flash.py --speed 300               # снизить скорость SWD при сбоях связи
python3 flash.py --dump backup.bin         # СНАЧАЛА снять бэкап текущей прошивки!
python3 flash.py --build-only out.bin      # собрать .bin без прошивки (тест без платы)
python3 flash.py --backend openocd         # использовать OpenOCD вместо pyOCD
```

**Совет:** перед первой прошивкой стоит снять бэкап заводской прошивки конкретной
платы: `python3 flash.py --dump my_factory_backup.bin`. Версии плат различаются -
собственный бэкап всегда вернёт всё как было.

### Проверка флэшера без платы

Можно убедиться, что всё работает, ничего не подключая:

```bash
python3 flash.py --list                                  # видит ли прошивки
python3 flash.py --help                                  # все опции
# собрать откалиброванный .bin и проверить, что меняется ровно 1 байт:
python3 flash.py --firmware mod90c --calibrate 11 --build-only /tmp/t.bin
cmp -l firmware/mod_90c.bin /tmp/t.bin                   # должна быть 1 строка (адрес C1)
```

`--build-only` плату не трогает. Реальная прошивка возможна только при подключённом
отладчике и **снятом 220 В** (см. раздел безопасности).

## Калибровка температуры

Датчик **нелинеен**: на холодную он показывает почти верно, но **при нагреве
занижает** - чем горячее, тем сильнее. Калибровка добавляет постоянную поправку,
которую стоит подобрать под  вашу **рабочую точку **.

**Рекомендуется смещение `+11 °C` (≈ +20 °F)** - почему именно так:

| | без калибровки | с `+11 °C` |
|---|---|---|
| на холодную (в комнате ~23 °C) | дисплей ~23 °C (точно) | дисплей ~34 °C (завышает) |
| при нагреве до реальных 90 °C | дисплей только ~79 °C | дисплей ~90 °C (точно) |

Без поправки на 90 °C дисплей застревает на ~79, регулятор считает, что «недогрел»,
и гонит PTC-нагреватели дальше → срабатывает тепловая отсечка, **постоянные щелчки**
и заниженные/ложные показания. С `+11` рабочие 90 °C показываются и регулируются
верно - `90 = 90` (ценой неточности на холодную, но это не важно, сушим-то горячим).

В интерактивном меню достаточно нажать **Enter** (применятся +11). Можно задать
своё число - но для 90 °C около **+11** обычно и нужно. Смещение **принимает
дробные значения** (например, `10.5` или `11.3`) и **отрицательные** - если
дисплей, наоборот, завышает (например, `-3`, предел ±30 °C).

> Смещение задаётся в **°C** (внутренняя единица прошивки). Для термометра в
> °F: разницу перевести в °C (поделив на 1.8). Например, дисплей 174 °F,
> термометр 194 °F → разница 20 °F → `20 / 1.8 ≈ 11` → смещение **11**.

**Если при ~90 °C слышны щелчки** - стоит увеличить смещение ещё на пару градусов
(например, до `+12…+13`). Чем выше смещение, тем раньше регулятор отсекает нагрев,
поэтому выход нагревателя не доходит до фактических ~120 °C и биметаллическая
защита перестаёт отщёлкиваться. Цена - реальная температура камеры станет на
пару градусов ниже выставленной (обычно это приемлемо).

**Как измерить смещение под свой экземпляр:**

1. Вставить термометр (термопару) в **переднее отверстие для PTFE-трубки**.
2. Прогреть камеру, дать температуре устаканиться.
3. Сравнить, что показывает **сушилка** и что **термометр**.
4. Смещение = `термометр − дисплей`. Пример: дисплей 79, термометр 90 → смещение **+11**.

**Как применить:**

```bash
python3 flash.py --firmware mod90c --calibrate 11    # +11 °C (рекомендуется)
python3 flash.py --firmware mod90c --calibrate 0     # без калибровки (завод)
```

или просто `python3 flash.py` - в интерактивном меню смещение спрашивается отдельно
(Enter = рекомендуемые +11, `0` = без калибровки, либо своё число).

Поправка едина для **обеих камер** (используется одна общая константа датчика).
После прошивки стоит сверить термометром ещё раз и при необходимости перепрошить с
уточнённым числом.

> Технически калибровка меняет одну float-константу `C1` (`T = ADC·K − C1`,
> заводское `C1 = 50.0`) на `50.0 − смещение`. Подробности - в [`docs/PATCHES.md`](docs/PATCHES.md).

## Щелчки и градиент температуры - это нормально

При сушке слышны **щелчки** в районе нагревателя, а температура у задней стенки и
у фронта заметно разная. Это **штатное поведение**, не поломка:

- **Задняя стенка (выход горячего воздуха):** на фото **102 °C**, а предел -
  **около 120 °C / 248 °F**. PTC-нагреватели выдают максимум ~120 °C, дойдя до этого
  предела отключаются, остывают и снова включаются. Отсюда и щелчки - это срабатывает
  тепловая защита нагревателя, не дефект прошивки.
- **Фронт камеры (где термометр / где лежит филамент):** ~**90 °C / 194 °F**. Это
  рабочая температура, по ней и идёт регулировка - именно её показывает дисплей
  (после калибровки - верно).
- **Разница фронт/зад:** около **30 °C (54 °F)**, то есть у задней стенки воздух
  примерно на **~33 % горячее**, чем у фронта (эквивалентно: фронт на ~25 % холоднее
  выхода). Это нормальный температурный градиент проточной камеры.

Иными словами: щёлкает не «глюк прошивки», а нагреватель на своём пределе у выхода,
пока фронт держит заданные 90 °C (194 °F).

**Если щелчки мешают** - их можно убрать, **увеличив смещение калибровки** (например,
`+12…+13` вместо `+11`): регулятор отсечёт нагрев чуть раньше, выход не дойдёт до
~120 °C, и биметаллическая защита не сработает. Реальная температура при этом будет
на пару градусов ниже выставленной. См. [«Калибровка температуры»](#калибровка-температуры).

## Две прошивки - в чём разница

| Файл | Макс. t | Кому |
|------|:------:|------|
| `firmware/mod_90c.bin` | 90 °C / 194 °F | поднять предел до 90 °C |
| `firmware/stock_factory_75c.bin` | 75 °C / 167 °F | откат к заводской |

### Про E4 и безопасность

**E4** - код неисправности датчика/нагрева. Мод **не выпиливает E4-защиту целиком**:
если реально отсоединить/закоротить температурный датчик - **E4 по-прежнему сработает**
и нагрев заглушится (проверено: при отключении датчика ошибка выходит).

Что мод действительно ослабляет - это **watchdog недогрева**: заводская прошивка
ругалась E4, если температура не достигла **85 % от уставки** (`0.85 × 90 = 76.5 °C`),
а зажатый на 75 °C нагрев до этого порога не доходил → **вечный E4**. Мод убирает
именно этот ложный триггер, чтобы можно было дойти до 90 °C. Аппаратная защита тоже
остаётся - PTC-нагреватели самоограничиваются по своей конструктивной температуре.

## Что именно меняет мод (для любопытных)

Мод - это байтовые патчи заводской прошивки (128 КБ, грузится с `0x08000000`).
Подробная карта - в [`docs/PATCHES.md`](docs/PATCHES.md). Кратко:

- клампы целевой температуры `75 → 90 °C` и `45 → 1 °C` (зоны 1 и 2),
- расширение диапазона уставки в меню до 90,
- снятие клампа отображаемой/регулируемой температуры на 80.0 °C,
- перенаправление watchdog недогрева мимо обработчика E4 (сенсорная E4-защита цела).

Функция датчика и регулировка по уставке **не тронуты** - нагрев выключается
при достижении цели как обычно.

> Хотите копать глубже / дорабатывать прошивку (своя калибровка, обороты
> вентиляторов, UI)? Наблюдения по плате и реверсу - в [`docs/REVERSE.md`](docs/REVERSE.md).

## Если что-то пошло не так

- **Отладчик не виден / `No available debug probes`** → проверить кабель и драйвер
  (Windows: WinUSB через [Zadig](https://zadig.akeo.ie/)), снизить `--speed` до `300` или `200`.
- **`unable to connect` / `init mode failed`** → плата не запитана от 5 В,
  плохой контакт SWDIO/SWDCLK/GND, или слишком высокая скорость.
- **pyOCD: `Target type ... not found`** → пак не успел поставиться, вручную
  `pyocd pack install gd32f303cb` (нужен интернет), затем повторить.
- **pyOCD капризничает на конкретной плате** → можно перейти на OpenOCD: `--backend openocd`.
- **Залита не та прошивка / плата ведёт себя странно** → залить `stock` (или свой бэкап).
  Кирпичом от прошивки плата не становится - SWD всегда доступен.
